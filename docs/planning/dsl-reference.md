# dsl-exp - Schema Reference

This document explains the fields and structure of the dsl-exp.

## 1. Workflow Structure

The top-level object represents a Workflow.

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `name` | string | Yes | The name of the workflow. |
| `description` | string | No | A brief description of what the workflow does. |
| `version` | string | No | The version of the DSL syntax (e.g., "0.1"). |
| `nodes` | array | Yes | An ordered list of **Nodes** that define the execution flow. |

## 2. Common Node Properties

All nodes share these properties.

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `id` | string | Yes | Unique identifier. Must start with a letter/underscore and contain only alphanumerics/underscores (`^[a-zA-Z_][a-zA-Z0-9_]+$`). |
| `type` | string | Yes | The type of the node. See Section 3. |
| `next` | string | No | The `id` of the next node to execute. If omitted, defaults to the next node in the list. |
| `visibility` | enum | No | Controls user output. Default: `public`. <br> - `public`: Stream to user & save to memory. <br> - `silent`: Save to memory only (internal thought). <br> - `ephemeral`: Stream to user only (do not save). |
| `memory_policy` | enum | No | Controls scope memory merge. Default: `result_only`. <br> - `result_only`: Only the final result of the scope is kept. <br> - `full`: All history in the scope is kept. <br> - `summary`: (Advanced) Summarize scope history. |

## 3. Node Types

### 3.1 `generate` (LLM)
Invokes an LLM to generate text or tool calls.

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `model` | string | Yes | The model identifier (e.g., `gpt-4`). |
| `system_prompt` | string | No | The system instruction. Supports Jinja2 templates. |
| `temperature` | number | No | Sampling temperature (0.0 - 1.0). |
| `context_mode` | enum | No | Default: `full`. <br> - `full`: Pass full conversation history. <br> - `none`: Pass only system prompt + user input. <br> - `window`: Pass last N messages (implementation dependent). |

### 3.2 `tool` (Executor)
Executes a tool call generated by a previous `generate` node.

*No specific properties. It automatically looks for the last `ToolCall` message in the history.*

### 3.3 `parallel` (Flow)
Executes multiple branches concurrently.

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `branches` | array | Yes | List of branch objects. Each branch has a `nodes` list. |
| `reducer` | Node | No | An optional Node definition (usually `generate`) to run *after* all branches finish, to merge results. |

### 3.4 `selector` (Branching)
Routes execution based on LLM classification.

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `model` | string | No | The model to use for classification. |
| `system_prompt` | string | No | Instructions for classification. |
| `options` | array | Yes | List of cases. |

**Option Object**:
| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `case` | string | Yes | Description of the condition (e.g., "User asks for weather"). |
| `next` | string | Yes | The target Node ID to jump to. |

### 3.5 `group` (Scope)
Groups a set of nodes into a local scope (useful for applying `memory_policy` to a sequence of steps).

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `nodes` | array | Yes | The list of nodes inside the group. |

### 3.6 `noop` (Marker)
Does nothing. Useful as a jump target (e.g., an "end" node) or a placeholder.
